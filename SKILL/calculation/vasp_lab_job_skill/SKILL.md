# vasp-lab-job

This skill is **script-first**. Do not only explain parameters in Markdown when a
calculation input should be made. Use the Python scripts in `scripts/` to create
`POSCAR`, `INCAR`, `KPOINTS`, `POTCAR`, copy the correct SGE submit script, and
optionally submit with `qsub`.

Do **not** use the legacy `vasp-job` YAML job-spec interface, `queue: { preset:
auto }`, `extends`, or `queue.preset` unless the user explicitly asks for that
old workflow.

## File layout

```text
vasp-lab-job/
  SKILL.md
  agents/openai.yaml
  scripts/
    make_vasp_inputs.py          # main execution path
    vasp_lab_common.py           # shared helpers
    analyze_convergence.py       # reads OUTCAR/OSZICAR and selects kpts/ENCUT
    diagnose_vasp_failure.py     # recovery classifier
    MakeGasCalc.py               # compatibility wrapper
    MakeBulkCalc.py              # compatibility wrapper
    MakeSlabCalc.py              # compatibility wrapper
    MakeAdsCalc.py               # compatibility wrapper
    MakeOxideSlabAd.py           # compatibility wrapper
  assets/
    submit_vasp_64.sh
    submit_vasp_48.sh
    submit_vasp_gam_64.sh
    submit_vasp_gam_48.sh
  references/
    defaults.yaml                # machine-readable default/lab profiles
    literature_parameters.yaml   # paper-derived profiles to be filled with DOI/citation
```

## Parameter-source policy

1. User-provided overrides win.
2. Prefer a paper/literature profile when the user provides a paper, DOI,
   citation, or a filled profile in `references/literature_parameters.yaml`.
3. If no paper-derived profile is available, use the lab fallback profiles in
   `references/defaults.yaml` and say they are lab defaults, not paper-derived
   final evidence.
4. Do not invent literature parameters. If a value such as `U`, `ENCUT`,
   smearing, functional, or dispersion is claimed to come from a paper, the
   profile must include a citation/DOI/source note.

Use this pattern to use a paper profile:

```bash
python scripts/make_vasp_inputs.py \
  --calc-type ads \
  --poscar POSCAR_NH3 \
  --outdir ads/NH3_site01 \
  --selected-settings slab_convergence.yml \
  --parameters-yaml references/literature_parameters.yaml \
  --profile <paper_profile_name> \
  --submit
```

## Main script

Use `scripts/make_vasp_inputs.py` for actual input generation.

Common options:

```bash
--calc-type gas|bulk|slab-kconv|slab-encut|slab-final|ads|oxide-ads|freq
--poscar <POSCAR-or-CONTCAR>
--outdir <calculation-directory>
--project-root <project-root>
--selected-settings slab_convergence.yml
--profile <parameter-profile>
--parameters-yaml references/defaults.yaml
--set key=value                  # repeatable VASP parameter override
--cores 64|48
--submit                         # call qsub after input generation
--dry-run-submit                 # copy submit script but do not call qsub
```

When the user asks to submit and the input files are valid, run with `--submit`.
Do not check whether compute nodes are currently free; let SGE queue pending
jobs.

## Submit-script selection

The Python script implements this rule:

- Gas jobs always use standard `vasp_std` submit scripts, even when
  `kpts=[1,1,1]`.
- Non-gas jobs with `kpts=[1,1,1]` use `vasp_gam` submit scripts.
- Non-gas jobs with other k-point meshes use standard `vasp_std` submit scripts.
- Default core count is 64 unless the user requests 48.

Templates:

```text
64 std  -> assets/submit_vasp_64.sh
48 std  -> assets/submit_vasp_48.sh
64 gam  -> assets/submit_vasp_gam_64.sh
48 gam  -> assets/submit_vasp_gam_48.sh
```

The actual SGE command is always run from inside the calculation directory:

```bash
qsub <selected_submit_script>
```

## 0. Gas calculation

Use the script, not a Markdown-only recipe. The gas lab default profile is in
`references/defaults.yaml` under `gas_lab_standard`.

```bash
python scripts/MakeGasCalc.py \
  --poscar POSCAR \
  --outdir gas/<molecule_name> \
  --submit
```

Equivalent main command:

```bash
python scripts/make_vasp_inputs.py \
  --calc-type gas \
  --poscar POSCAR \
  --outdir gas/<molecule_name> \
  --submit
```

Gas uses `kpts=[1,1,1]` but still uses `submit_vasp_64.sh` or
`submit_vasp_48.sh`, not the gamma submit scripts.

## 1. Bulk optimization

Use a POSCAR generated by an upstream structure skill. Do not hard-code Pt or any
example bulk unless explicitly requested. Bulk calculations use `ENCUT=600` by
default.

```bash
python scripts/MakeBulkCalc.py \
  --poscar POSCAR \
  --outdir bulk/opt \
  --submit
```

After bulk convergence, use `bulk/opt/CONTCAR` to build the slab POSCAR with the
slab-building skill.

## 2. Slab k-point convergence

The slab POSCAR should come from the optimized bulk `CONTCAR`. Bottom two slab
layers should already be fixed by the slab-building skill. If needed, the script
can enforce a simple z-layer fix with `--fix-bottom-layers 2`, but do not guess
constraints silently.

Default k-point series is read from `references/defaults.yaml`:

```text
[1,1,1] -> [2,2,1] -> [3,3,1] -> [4,4,1] -> [5,5,1] -> [6,6,1]
```

Run:

```bash
python scripts/MakeSlabCalc.py \
  --poscar POSCAR_slab \
  --project-root . \
  --fix-bottom-layers 2 \
  --submit
```

This creates separate directories:

```text
slab/kconv/k111/
slab/kconv/k221/
slab/kconv/k331/
...
```

For non-gas `k111`, the script copies the gamma submit script. For all other
k-point meshes, it copies the standard submit script.

After the jobs finish, analyze:

```bash
python scripts/analyze_convergence.py \
  --type kpoint \
  --root slab/kconv \
  --write slab_convergence.yml
```

The analyzer reads final energies from `OUTCAR` or `OSZICAR`, reports a table,
and records the smallest mesh where the adjacent energy change is below the
configured tolerance.

## 3. Slab ENCUT convergence

Start only after `slab_convergence.yml` contains `selected_kpts`.

```bash
python scripts/make_vasp_inputs.py \
  --calc-type slab-encut \
  --poscar POSCAR_slab \
  --selected-settings slab_convergence.yml \
  --project-root . \
  --fix-bottom-layers 2 \
  --submit
```

Default ENCUT series:

```text
400 -> 450 -> 500 -> 550 -> 600
```

The script creates:

```text
slab/encut_conv/encut400/
slab/encut_conv/encut450/
...
```

After the jobs finish:

```bash
python scripts/analyze_convergence.py \
  --type encut \
  --root slab/encut_conv \
  --write slab_convergence.yml
```

## 4. Final clean slab

Run after both `selected_kpts` and `selected_encut` are recorded.

```bash
python scripts/make_vasp_inputs.py \
  --calc-type slab-final \
  --poscar POSCAR_slab \
  --selected-settings slab_convergence.yml \
  --outdir slab/final \
  --fix-bottom-layers 2 \
  --submit
```

## 5. Slab + adsorbate

Use POSCAR files generated by an upstream adsorbate-placement skill. Reuse the
selected clean-slab `kpts` and `ENCUT`; do not hard-code `kpts=[5,5,1]` or
`encut=400`.

Single adsorbate calculation:

```bash
python scripts/MakeAdsCalc.py \
  --poscar POSCAR_NH3_site01 \
  --outdir ads/NH3_site01 \
  --selected-settings slab_convergence.yml \
  --submit
```

Batch over `POSCAR*` files:

```bash
python scripts/make_vasp_inputs.py \
  --calc-type ads \
  --scan-poscars 'POSCAR*' \
  --project-root . \
  --selected-settings slab_convergence.yml \
  --submit
```

For Co/Ni oxide slab+adsorbate jobs using the uploaded oxide-style magnetic
moments and LDA+U values, use:

```bash
python scripts/MakeOxideSlabAd.py \
  --scan-poscars 'POSCAR*' \
  --selected-settings slab_convergence.yml \
  --submit
```

That oxide profile is marked as requiring literature verification in
`defaults.yaml`; use a paper-derived profile when possible.

## 6. Frequency calculation

Run only after a relaxed slab+adsorbate endpoint exists. Start from the relaxed
`CONTCAR`. Use the same selected `kpts` and `ENCUT`. Frequency-specific settings
are encoded in the `freq_adsorbate_base` profile:

```text
IBRION=5, POTIM=0.015, NFREE=2, NSW=1, ISIF=0
```

Fix all slab atoms and keep adsorbate atoms mobile. Prefer explicit mobile atom
indices because adsorbate elements can overlap slab elements.

```bash
python scripts/make_vasp_inputs.py \
  --calc-type freq \
  --poscar ads/NH3_site01/CONTCAR \
  --outdir freq/NH3_site01 \
  --selected-settings slab_convergence.yml \
  --mobile-indices 97-104 \
  --submit
```

If element-based selection is safe for the system:

```bash
python scripts/make_vasp_inputs.py \
  --calc-type freq \
  --poscar ads/NH3_site01/CONTCAR \
  --outdir freq/NH3_site01 \
  --selected-settings slab_convergence.yml \
  --adsorbate-elements N H \
  --submit
```

## Overrides

Use `--set` for user-requested or paper-derived one-off overrides:

```bash
python scripts/make_vasp_inputs.py \
  --calc-type slab-final \
  --poscar POSCAR_slab \
  --selected-settings slab_convergence.yml \
  --set ediff=1e-6 \
  --set algo=Normal \
  --submit
```

## Failure diagnosis

After a job finishes or fails:

```bash
python scripts/diagnose_vasp_failure.py --dir <calculation_directory> --max-retries 3 --retry-count <n>
```

Use the JSON `recommended_action` to decide whether to continue from `CONTCAR`,
switch `ALGO`, reduce `POTIM`, inspect the structure, or drop the candidate.

## Common mistakes

- Do not use `queue: { preset: auto }` in this skill.
- Do not wait for free nodes before `qsub`; SGE will queue jobs.
- Do not use `vasp_gam` for gas jobs.
- Do not overwrite convergence directories.
- Do not claim parameters are from papers unless the profile includes a paper
  citation/DOI/source note.
- Do not rely on element names alone to choose mobile atoms for frequency if the
  adsorbate and slab share elements; use `--mobile-indices`.
